# 労働アップデート設計

## 1. 目的

従来の労働コマンドは選択すると即座に実行される。本アップデートでは日替わりの候補から労働を選択する方式に変更し、時間・体力・収入・戦闘リスクを比較する余地を作る。

## 2. 労働マスタ

初期解放済みの労働は以下の5種類とする。数値は初期調整値であり、将来のバランス調整対象とする。

| 名前 | 時間コスト | 報酬 | 体力コスト | 戦闘発生確率 | 戦闘危険度 | 解放条件 |
|---|---:|---:|---:|---:|---:|---|
| 荷役 | 4時間 | 30 PLN | 25 HP | 15% | 1 | なし |
| 橋作り | 6時間 | 60 PLN | 40 HP | 15% | 2 | なし |
| 針仕事 | 2時間 | 15 PLN | 10 HP | 0% | 0 | なし |
| 採掘 | 7時間 | 130 PLN | 50 HP | 25% | 3 | なし |
| 採取 | 5時間 | 100 PLN | 40 HP | 25% | 2 | なし |

労働を識別するID、名称、説明文、各コスト、報酬、戦闘発生確率、戦闘危険度、解放条件を定義できる構造とする。画像素材との対応付けも可能にする。既存の能力値・アイテムによる補正は既存仕様に従う。

将来的には別コマンドからコストを支払って労働を解放する。追加労働の内容および解放コマンドは今回の実装対象外とする。

## 3. 日替わり抽選

- 初日を含む各日の開始時に、解放済み労働から2種類を均等確率・重複なしで抽選する。
- 抽選結果はゲーム状態として保持し、その日の終了まで固定する。
- ダイアログの開閉、選択変更、労働実行による再抽選は行わない。
- 同じ労働を、実行条件を満たす限り何度でも実行できる。
- 日付が変われば新しい候補を抽選する。
- 将来、労働を解放した場合も当日の候補は固定し、翌日の抽選から反映する方針とする。

## 4. 労働の実行

### 4.1 実行条件

残り時間が実際の時間コスト以上であり、補正・端数処理後にHPが1以上残ること。金の砂時計を所持し、残り時間が正の場合は時間不足でも実行可能とし、残り時間を0にする。戦闘HPは通常HPとは独立する。

HPが0になった時点で死亡し、ゲームオーバーとなる。労働コストと現在HPが等しい場合も実行不可とする。

実行不可の労働も一覧に残し、選択・詳細確認は可能とする。時間不足・体力不足の理由を表示することを推奨する。

### 4.2 処理の流れ

1. メニューの「労働」からダイアログを開く。この時点では労働を実行しない。
2. 候補を選択し、詳細を確認する。
3. 労働開始ボタン押下時に実行条件を再確認し、二重実行を防止する。
4. 時間・HPを消費し、労働報酬を反映する。死亡判定は既存のゲームオーバー処理に接続する。
5. 生存している場合、労働別の戦闘発生確率に従って戦闘判定を行う。
6. 戦闘が発生した場合は現行オートバトルを利用する。結果確認まで労働・購入・翌日移行を禁止する。通常HPへの追加損失や勝敗による労働報酬の変更は行わない。
7. 生存していれば画面の状態と労働結果を更新し、ダイアログを開いたままにする。

報酬付与・日付変更などの厳密な処理順序は既存ゲームループとの整合性を優先する。日付が変わった場合は候補を更新し、古い候補への選択を解除する。

## 5. 労働ダイアログ

### 5.1 レイアウト

承認済みの画面イメージに従い、上部にステータス、左側に候補一覧、右側に詳細と実行操作、下部に結果を配置する。

```text
┌──────────────────────────────────────────────────┐
│ 労働       残り時間   現在HP/最大HP   所持PLN  × │
├──────────────────┬───────────────────────────────┤
│ 本日の労働        │ 選択した労働の名称・説明       │
│ ┌──────────────┐ │                               │
│ │ アイコン 採掘 │ │ 時間・HP・報酬   労働イラスト │
│ │ 報酬/時間/HP  │ │ 戦闘発生確率                   │
│ └──────────────┘ │ 戦闘危険度                     │
│ ┌──────────────┐ │                 [労働開始]     │
│ │アイコン 針仕事│ │                               │
│ │ 報酬/時間/HP  │ │                               │
│ └──────────────┘ │                               │
├──────────────────┴───────────────────────────────┤
│ 結果イラスト     直近の労働結果                   │
│                 獲得PLN・消費HP・消費時間         │
└──────────────────────────────────────────────────┘
```

### 5.2 各領域の詳細

| 領域 | 表示内容・特徴 |
|---|---|
| ヘッダー | 労働のタイトル、残り時間、現在HP/最大HP、所持プルン、閉じるボタン。処理後に最新状態を表示する |
| 左側・候補一覧 | 本日の2種類を縦に並べた同寸法のカード。アイコン、名称、報酬、時間コスト、体力コストを表示する。単一選択式で、選択中のカードを枠線や背景色で区別する |
| 右側・詳細 | 選択した労働の名称、説明文、時間コスト、体力コスト、報酬、戦闘発生確率、戦闘危険度を表示する |
| 右側・イラスト | 選択した労働に対応するぷるぷるの姿を表示する。縦横比を維持して領域内に収める |
| 右下・実行操作 | 労働開始ボタン。選択と実行を分離し、追加の確認ダイアログは設けない方針 |
| 下部・結果 | 直近の労働名、実際に獲得した報酬、消費時間、HP損失および結果用イラスト。戦闘結果を併記し、戦闘による通常HP損失がないことを示す |

### 5.3 操作と状態

- カードを選択すると詳細とイラストが切り替わる。選択だけでは労働を実行しない。
- 未選択時は案内を表示して実行ボタンを無効化する方針とする。
- 実行条件を満たさない場合も選択できるが、労働開始ボタンは無効とする。
- 労働実行中は候補選択、実行、閉じる操作を一時的に無効化する。
- 労働完了後はダイアログを閉じず、同日であれば選択状態を維持する。
- 結果は選択変更で消さず、次回の労働結果で上書きする。
- 結果確認のための追加ボタンは設けない。
- 初回の結果未表示時も下部領域の大きさを維持する。
- 候補一覧・詳細・画像・結果の領域は固定し、説明文や画像サイズによるレイアウトの変動を防ぐ。画像未登録時は仮表示とする。
- 美術方針は既存の絵本的・水彩的な方向性に合わせる。具体的な寸法は実装時に調整する。

## 6. 労働演出

反復操作の妨げにならない短い演出とする。演出時間は全体で0.8～1.2秒程度を目安とする案であり、確定値ではない。

| 段階 | 演出案 |
|---|---|
| 開始 | 道具を構える。操作を一時的に無効化 |
| 労働中 | ぷるぷるの伸縮・振動・上下動と、小物や簡易エフェクト |
| 完了 | 報酬の浮き上がり、ステータスおよび結果の更新 |
| 戦闘発生 | 頭上の「！」や驚く動作。オートバトル画面と結果を表示 |

労働ごとの演出例：荷役は木箱の重さでつぶれる、橋作りは金槌で小刻みに弾む、針仕事は針と布を使って左右に揺れる、採掘はつるはしと石の破片、採取はかごと舞う葉。

実装は段階的に進める。

1. レイアウトと機能を完成させ、画像は仮素材またはプレースホルダーとする。
2. 労働アイコン・労働中および結果用のイラストを追加する。
3. 共通アニメーションと労働別の軽いエフェクトを追加する。

## 7. 現在の戦闘処理と今回の範囲

現行オートバトルを維持し、発生確率を労働別の値に変更する。通常HPと戦闘HPは独立し、戦闘による通常HP損失はない。戦闘危険度0の場合は補正後の確率に関係なく戦闘を発生させない。確率補正自体は適用し、魔獣活発化は既存どおり+30ptとする。危険度1以上の値は保持・表示のみとし、敵能力やダメージ計算には使用しない。

## 8. 将来の戦闘構想（今回の実装対象外）

- 労働ごとに敵のステータス傾向を持たせ、得意な労働に合わせた能力ビルドを可能にする。例：採掘では防御力の高い石系の敵。
- 危険度別の敵プールにする案や、危険度と労働別傾向を併用する案も検討する。
- 現行ATB方式のオートバトルを基盤とし、将来の逃走は通常の戦闘行動として扱う。素早さは行動頻度、敵の特性は逃走成功率に影響する方向。
- 戦闘前の命令案：「勝て」（逃げずに戦う）、「逃げろ」（逃走を試み続ける）、「がんばれ」（HP30%以下などで逃走へ移行）。
- 戦闘方針の追加・詳細設定をショップアイテムで解放する案もある。
- 命令選択ごとにぷるぷるが戦闘結果を大まかに予測し、青ざめて震える、冷や汗、キリッとした顔などの表情で伝える。重要でない戦闘の意思決定負担を軽減することが目的。確率的な逃走を含む予測方法は未定。
- 逃走時のデメリットはHP損失のみとし、労働報酬は維持する方向だが未確定。
- 運による死亡は許容する。ただし、稀な不運だったのか、自らリスクを選んだ結果だったのかをプレイヤーが理解できるようにする。

## 9. 未確定事項

| 項目 | 現時点の扱い |
|---|---|
| HPと体力コストが等しい場合 | 実行不可（確定） |
| 戦闘危険度の適用方法 | 0は戦闘禁止。1以上の戦闘計算への反映は保留 |
| 敵プール・敵ステータス傾向 | 保留 |
| 労働解放の方法・追加労働 | 今回の対象外 |
| 説明文・画像素材 | 仮表示で可 |
| ダイアログの具体的な寸法 | 実装時に調整 |
| 演出時間・素材・詳細 | 段階的に実装 |
| 逃走・戦闘予測 | 将来の戦闘設計で検討 |


## 10. 実装時の確定事項（2026-11-22）

- 補正は既存の割合 → 固定値 → 明示倍率 → 最終資源の切り捨てを維持する。
- 労働の実報酬は小目標報酬・生活費と分けて結果に保持する。
- 王冠・腕輪は労働前の状態で判定し、熟練の作業着は完了した労働の次回以降に作用する。
- 候補外の労働や旧APIによる選択省略は実行できない。
- 第1段階として固定レイアウトと機能を実装する。労働専用素材・演出は後続段階とし、今回は仮表示とする。
