# 小目標 設計メモ（暫定）

更新日：2026-10-23

> 本資料は実装に向けた仮仕様。数値・判定タイミング・報酬の換算方法など、未確定事項は今後調整する。

## 1. 目的・基本方針

- 小目標は、プレイヤーに一定期間の**試練**を提示する仕組み。イベントは別の仕組みとして扱う。
- 成果の大きさだけでなく、限られた時間・プルンを**何に割り振るかという選択**を重視する。
- 失敗時のペナルティは設けない。達成報酬を受け取れないことだけが不利益。
- 最初は性質の異なる目標を少数実装し、後から類似・派生目標を増やしてよい。

## 2. 発生・期限

- 小目標が発生していない場合、**日数の1の位が5の日**に次の小目標を予告する。
- 予告から**約15日後**を期限とする。
- 目標と報酬は**予告時に同時に提示**する。
- 達成すると、提示済みの報酬を受け取る。報酬選択制は現時点では想定しない。
- 達成後、次の小目標の予告までの挙動は上記発生ルールを基本とする（細部未確定）。

## 3. 小目標の種類

| 種類 | 達成条件（仮） | 判定 | 実装方針 |
| --- | --- | --- | --- |
| 資産到達型 | 期限までに X プルンに到達する | 期間内に一度でも到達すれば即達成 | 先行実装 |
| 資産維持型 | 期限時点で X プルンを保有する | 期限時点の所持量で判定 | 先行実装 |
| 労働型 | 期間中に N 回労働する | 予告後の労働回数を累積 | 先行実装 |
| 成長型 | 期間中に能力を N 回強化する | 予告後の強化回数を累積 | 先行実装 |
| 討伐型 | 一定以上の強さの魔獣に勝利する | 対象条件を満たす戦闘の勝利 | 戦闘システム実装後に追加 |

### 資産到達型

- **提示時の保有プルン量に応じて目標額を設定する**。
- 提示時点で容易に即達成できる目標にならないよう調整する。
- 目標提示直前にプルンを使い切ると有利になる問題には注意する。進行度別の最低目標額などは対策候補であり、未決定。

### 資産維持型

- 期限までに必要額を確保し、期限時点で保有している必要がある。
- **期限当日の開始時点か終了時点かは未決定**。
- 資産到達型とは異なり、早期に目標額へ到達しても即達成にはならない。

### 労働型

- 稼いだ金額ではなく、**労働という行動を選んだ回数**を条件とする。
- 他のコマンドに使える時間との競合を生む。

### 成長型

- 能力の到達値ではなく、**期間中の強化回数**を条件とする。
- 現時点で能力は1種類のみ。将来は強化対象の能力を指定する方式も許容する。
- 能力強化1回のコストと上昇幅は常に一定。ただし、1→2の強化は30→31より相対的な価値が高い、という設計思想。

### 討伐型（後日）

- 特定の敵ではなく、**一定以上の強さの魔獣に勝利**することを条件とする。
- 戦闘は簡易版も未実装のため、現時点では小目標として実装しない。

## 4. 報酬

- 報酬候補：**プルン、能力強化、アイテム**など。
- 目標の予告と同時に具体的な報酬を提示し、達成時にそれを受け取る。
- 簡単な目標に過大な報酬が付かないよう、報酬価値を**共通の一次元指標**に換算して管理する方針。
- 換算式・各報酬の価値・難易度との対応関係は未確定。
- 永続的な能力強化と消費可能なプルンでは長期的価値が異なるため、調整時に考慮する。

## 5. スケーリング

- 進行度に応じて目標値をスケーリングできる余地を残す。
- 資産到達型は提示時の保有量を目標設定に利用する。
- 労働回数・強化回数・資産維持額・討伐の要求強さの具体的な計算方法は未決定。

## 6. 未決定事項

- 期限当日の判定タイミング（特に資産維持型）。
    - (決定)期限当日の一日終了時に判定する。
- 目標の選出方法、同一目標の連続出現可否。
    - (決定)選出はランダム、連続出現なし
- 目標値と報酬価値の算定式、スケーリング基準。
- 報酬の具体的な種類・数量。
- 達成時の報酬付与タイミングや表示方法。
    - (決定)達成判定が出て、次の操作可能タイミングに割り込むようにする。
- 予告日・期限日・達成日が重なった場合の処理順。
    - 今のところロジック的には起こりえない。考慮なしで進める。

## 7. 初期実装の範囲

1. 小目標の予告、期限、進捗、達成・失敗判定。
2. 予告時の報酬提示と達成時の付与。
3. 資産到達型・資産維持型・労働型・成長型の4種類。
4. 討伐型は戦闘実装後に追加。

※ 本メモの数値例（X、N、約15日など）は確定仕様ではない。
