# オートバトル基本設計

## 1. 概要

労働後に発生するアクシデントとして、オートバトルを実装する。

プレイヤーは戦闘中に操作を行わず、主人公と敵がそれぞれの能力値に従って自動的に攻撃する。

通常戦闘は、危険度が高い代わりに報酬も高い労働に対するリスク要素として位置付ける。

将来的には100日目の巨大魔獣戦などにも利用する可能性があるが、今回の設計対象には含めない。

### 基本方針

- 戦闘は専用ダイアログで表示する。

- 主人公と敵が自動的に攻撃を繰り返す。

- 行動順は素早さによって決まる。

- 戦闘中のHPは通常のHPとは別に管理する。

- どちらかの戦闘中HPが0になった時点で終了する。

- 戦闘自体は単純にし、育成方針と労働選択に戦略性を持たせる。

---

## 2. 戦闘パラメータ

主人公と敵は共通して、以下の4種類のパラメータを持つ。

| パラメータ | 説明              | 初期値 |
| ----- | --------------- | --- |
| 攻撃力   | 相手に与えるダメージを増やす  | 10  |
| 防御力   | 相手から受けるダメージを減らす | 10  |
| タフさ   | 戦闘中の最大HPに影響する   | 100 |
| 素早さ   | 行動ゲージの増加速度を決める  | 50  |

### 2.1 戦闘中HP

- 通常のHPとは独立した値とする。

- 戦闘開始時にタフさに基づいて生成する。

- 戦闘ごとに新しく生成し、前回の戦闘中HPは引き継がない。

- 戦闘中HPが0になったキャラクターは敗北する。

初期仕様では、タフさの値をそのまま戦闘中の最大HPとする案を採用する。

通常HPへのダメージ反映方法は別途決定するため、一旦実装しない。

### 2.2 素早さと攻撃速度

内部では素早さを行動ゲージの増加量として扱う。

画面では、直感的に理解しやすいよう攻撃速度（atk/s）として表示する。

**表示用攻撃速度 = 素早さ ÷ 100**

| 内部素早さ | 攻撃速度       | 攻撃間隔   |
| ----- | ---------- | ------ |
| 25    | 0.25 atk/s | 4秒     |
| 50    | 0.50 atk/s | 2秒     |
| 100   | 1.00 atk/s | 1秒     |
| 150   | 1.50 atk/s | 約0.67秒 |
| 250   | 2.50 atk/s | 0.4秒   |

素早さには100の上限を設けず、1秒間に複数回の攻撃が可能とする。

---

## 3. ダメージ計算

防御力による割合軽減方式を採用する。

**ダメージ = 攻撃力 × 100 ÷ (100 + 相手の防御力)**

### 特徴

- 防御力が0の場合、攻撃力と同じダメージを受ける。

- 防御力が高くなるほど被ダメージが減少する。

- 防御力を高めても、完全に無傷にはならない。

- 防御力が低い場合、十分なダメージ軽減ができない。

- 防御力を上げるほど軽減率の伸びは緩やかになる。

### 計算例

攻撃力100の場合。

| 相手の防御力 | ダメージ  | 軽減率    |
| ------ | ----- | ------ |
| 0      | 100   | 0%     |
| 25     | 80    | 20%    |
| 50     | 約66.7 | 約33.3% |
| 100    | 50    | 50%    |
| 200    | 約33.3 | 約66.7% |
| 400    | 20    | 80%    |

計算式の100は調整可能な基準値として扱う。

**未確定事項**

- ダメージの整数化方法
  
  - A：適用直前に切り捨てる

- 最低ダメージの保証
  
  - A：1点とする。

## 4. 行動ゲージ

### 4.1 基本ルール

1. 戦闘開始時、双方の行動ゲージを0にする。

2. 時間経過に応じて、素早さに比例してゲージを増加させる。

3. ゲージが100に到達すると攻撃を実行する。

4. 攻撃後はゲージを100消費する。

5. 余剰ゲージがある場合は持ち越す。

6. どちらかの戦闘中HPが0になるまで繰り返す。

ゲージの増加速度は、1秒あたり素早さの値とする。

### 4.2 行動順

**行動ゲージが100に到達した時刻を基準に行動順を決定する。**

画面の描画更新タイミングによって行動順が変化しないようにする。

例えば、主人公の素早さ250、敵の素早さ150の場合。

| 経過時刻   | 行動     |
| ------ | ------ |
| 0.40秒  | 主人公が攻撃 |
| 約0.67秒 | 敵が攻撃   |
| 0.80秒  | 主人公が攻撃 |
| 1.20秒  | 主人公が攻撃 |
| 約1.33秒 | 敵が攻撃   |
| 1.60秒  | 主人公が攻撃 |

同じ時刻に双方が行動可能になった場合の優先順位は、主人公が先とする。

### 4.3 戦闘終了

攻撃によって戦闘中HPが0以下になった場合、直ちに戦闘を終了する。

終了後の攻撃は発生させない。

## 5. 戦闘画面

### 5.1 基本構成

戦闘は専用ダイアログで表示する。

画面は以下の領域から構成する。

| 領域  | 内容            |
| --- | ------------- |
| 上段左 | 主人公ステータス      |
| 上段右 | 戦闘風景          |
| 下段左 | 戦闘ログ          |
| 下段右 | 敵の画像・ステータス・説明 |

戦闘風景では主人公を左、敵を右に配置する。

主人公のステータス欄も左側に置き、キャラクターと情報の位置関係を一致させる。

### 5.2 戦闘風景

主人公と敵の画像を表示する。

それぞれのキャラクターには、以下の要素を配置する。

**キャラクター上部**

- 緑色の戦闘中HPバー

- 現在HPと最大HPの数値表示

**キャラクター中央**

- キャラクター画像

**キャラクター下部**

- 黄色の行動ゲージ

HPバーは最大HPに対する残量の割合を表示する。

行動ゲージは左から右へ増加し、攻撃が発生すると100を消費して次の行動に向けて再び増加する。

各バーの位置と寸法は固定し、数値の変化によってキャラクターや周囲のレイアウトが動かないようにする。

### 5.3 主人公ステータス欄

以下の情報を表示する。

- 戦闘中HP

- 攻撃力

- 防御力

- 攻撃速度（atk/s）

タフさは戦闘中HPの最大値として反映される。

### 5.4 敵情報欄

以下の情報を表示する。

- 敵の画像

- 敵の名前

- 敵のステータス

- 敵の説明文

敵情報欄の画像は、上部の戦闘風景で使用する画像とは別の表示領域とする。

### 5.5 戦闘ログ

攻撃の発生時刻、攻撃者、与えたダメージなどを表示する。

表示例：

```
1.00s 敵の攻撃！ 8ダメージを受けた！1.15s 自分の攻撃！ 12ダメージを与えた！
```

- 時刻は戦闘開始からの経過秒数とする。

- 小数点以下2桁程度で表示する。

- 内部計算では表示上の丸めに依存しない。

- ログが増えても画面全体のレイアウトを変化させない。

- ログ領域内だけをスクロール可能にする。

- ログを出すたびに改行を挟む。

## 6. 描画と演出

### 6.1 行動ゲージの表示

60fpsを目標に、行動ゲージが滑らかに伸びる表示とする。

ゲージを1秒ごとに段階的に増やす方式は採用しない。

戦闘計算と画面描画は分離し、描画フレームレートによって戦闘結果が変化しないようにする。

### 6.2 攻撃演出

初期実装では複雑なキャラクターアニメーションを必須としない。

攻撃の発生をプレイヤーが認識できる程度の簡単な演出を想定する。

将来的にはキャラクターの移動や攻撃モーションなどを追加できる余地を残す。

### 6.3 戦闘終了時

戦闘終了後は勝敗を表示する。

結果を確認してからダイアログを閉じる方式を想定する。

戦闘速度変更やスキップについては将来拡張候補とする。

## 7. 労働との関係

### 7.1 戦闘発生

戦闘トリガーは既存の仕組みを利用する。

労働終了後、戦闘発生判定によって戦闘が発生した場合、専用ダイアログを表示する。

戦闘中にゲーム内の労働時間を追加消費することは想定しない。

### 7.2 労働場所と敵の傾向

将来的には労働場所によって出現する敵のステータス傾向を変える。

例：

| 労働場所（仮） | 敵の傾向   |
| ------- | ------ |
| 魔獣の森    | 攻撃力が高い |
| 岩山の採掘場  | 防御力が高い |
| 巨獣の荒野   | タフさが高い |

これにより、プレイヤーの育成方針によって得意な労働場所と苦手な労働場所が生まれることを目指す。

労働場所ごとの敵の傾向は、プレイヤーがある程度把握できるようにする。

なお、今回の最小実装では、労働場所ごとの敵の抽選や種類の拡充は必須としない。

## 8. ゲーム全体における役割

ゲーム全体は、以下の3段階を基本的な進行方針とする。

| 段階  | 目的                      |
| --- | ----------------------- |
| 序盤  | 生存基盤を確立する               |
| 中盤  | 育成方針を決め、成長の準備をする        |
| 終盤  | 中盤までの育成成果を活用し、100日目に備える |

戦闘能力への投資は、危険な労働を選択しやすくするための手段となる。

戦闘そのものを複雑にするのではなく、能力の育成と労働場所の選択によって戦略性を生み出す。

## 10. 初期実装の範囲

今回の実装で優先するのは、以下の基本機能とする。

1. 主人公と敵の戦闘パラメータを用意する。

2. 戦闘開始時に戦闘中HPを生成する。

3. 行動ゲージを時間経過に応じて増加させる。

4. ゲージ到達時刻に従って攻撃を実行する。

5. 割合軽減方式でダメージを計算する。

6. どちらかの戦闘中HPが0になったら戦闘を終了する。

7. 専用ダイアログで戦闘を表示する。

8. HPバー・行動ゲージ・戦闘ログを更新する。

9. 戦闘結果を表示する。

通常HPへの影響や敗北ペナルティなど、未確定の仕様は実装前に別途決定する。

**初期実装の目標は、主人公と敵が自動的に攻撃し合い、その過程を専用ダイアログで観戦できる状態を完成させること。**
