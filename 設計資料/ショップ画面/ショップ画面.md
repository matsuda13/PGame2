# ぷるぷるサバイバル ショップ画面設計 Ver.1

## 1. 画面概要

ショップは、プレイヤーが所持プルンを消費して、永続的な効果を持つアイテムを購入する画面。

メイン画面からモーダルダイアログとして開き、閉じると元のメイン画面に戻る。

常設ショップと行商人は同じ画面構造を使用し、商人の画像・セリフ・商品一覧などの表示内容を切り替える。

### 基本方針

- 買い物中はゲーム内時間が進まない。

- 商品は各種類1個まで購入可能。

- 購入したアイテムは永続的に効果を発揮し、取り外し不可。

- 商品の選択と購入は別操作とする。

- 購入後もダイアログを閉じず、続けて買い物できる。

- 商品の価格は初期実装では一律500 PLN。

## 2. 画面構成

![](C:/Users/DevUser/AppData/Roaming/marktext/images/2026-10-31-23-18-57-image.png)

画面は大きく次の5領域に分ける。

| 領域   | 役割              |
| ---- | --------------- |
| ヘッダー | 店舗名・所持プルン・閉じる操作 |
| 左上   | 商人の立ち絵          |
| 左下   | カウンターと商人のセリフ    |
| 右上   | スクロール可能な商品一覧    |
| 右下   | 選択商品の詳細・購入操作    |

## 3. 各領域の詳細設計

### 3.1 ヘッダー

画面最上部に配置する固定領域。

| 要素     | 特徴・動作                      |
| ------ | -------------------------- |
| 店舗名    | 常設ショップ・行商人など、開いている店舗の名称を表示 |
| 所持プルン  | 現在の所持額を表示。購入後は即時更新         |
| 閉じるボタン | ダイアログを閉じてメイン画面に戻る          |

所持プルンは桁区切りを付けて表示する。

### 3.2 商人の立ち絵

画面左側の上部に配置する画像表示領域。

- 店舗ごとに異なる商人画像を表示できる。

- 画像の縦横比を維持し、表示領域内に収める。

- 画像サイズが異なっても周囲のレイアウトを崩さない。

- 画像が未登録の場合も、領域そのものは維持する。

- 初期実装では静止画のみを扱う。

商人画像は、商品一覧や詳細欄の操作によってサイズが変わらないようにする。

### 3.3 カウンター・セリフ領域

商人画像の下部に配置する固定領域。

カウンターの一部として見せつつ、商人のセリフを表示する。

- 複数行の文章を表示可能。

- 文章量が変わっても領域の大きさを変えない。

- セリフはプログラム内の商人セリフマスタから取得する。

- 商人ID `0` は全商人共通のセリフとする。

- 初期実装ではショップを開いたときに1件ランダム抽選する。

- 商品ホバーなどによる再抽選は将来拡張とする。

将来的には商人IDやゲーム状態に応じて、抽選候補を絞り込める構造を想定する。

### 3.4 商品一覧

画面右上の、最も広い領域を使用する。

縦方向に商品行を並べる、単一選択式のスクロールリストとする。

各商品行は以下の要素で構成する。

| 要素   | 特徴                     |
| ---- | ---------------------- |
| アイコン | 商品を表す小さな画像。全商品で表示寸法を統一 |
| 商品名  | アイコンの右側に表示             |
| 価格   | 商品行の右端に配置し、右揃え         |
| 購入状態 | 購入済みの場合は視覚的に区別         |
| 選択状態 | 選択中の商品行を背景色や枠線で強調      |

動作仕様：

- 商品行をクリックすると、その商品が選択される。

- 選択すると下部の商品詳細が切り替わる。

- 一度に選択できる商品は1件のみ。

- 購入済みの商品も一覧に残し、詳細を確認できる。

- 購入済みの商品はグレーアウト等で区別する。

- 商品が領域に収まらない場合、商品一覧の内部だけを縦スクロールする。

- 商品行の高さは一定とし、商品名が長い場合でも極端に高さが変わらないようにする。

商品一覧の並び順は、初期実装ではマスタの定義順とする。

### 3.5 商品詳細・購入領域

商品一覧の下部に配置する固定領域。

左側を商品説明、右側を購入操作に割り当てる。

| 要素    | 特徴              |
| ----- | --------------- |
| 商品名   | 選択した商品の名称       |
| 効果    | ゲーム上の効果を簡潔に表示   |
| 説明文   | 世界観や商品についての補足説明 |
| 購入ボタン | 選択商品の購入を実行      |

説明文が長い場合も、詳細領域が無制限に広がらないようにする。

商品未選択時は、商品名・効果・説明文の代わりに「商品を選択してください」と表示し、購入ボタンを無効化する。

## 4. 購入ボタンの状態

| 状態      | ボタン表示 | 操作  |
| ------- | ----- | --- |
| 商品未選択   | 購入    | 無効  |
| 所持プルン不足 | 購入    | 無効  |
| 購入可能    | 購入    | 有効  |
| 購入済み    | 購入済み  | 無効  |

購入可能な商品でボタンを押した場合、所持プルンを減算し、購入済み状態に変更して、アイテム効果を有効化する。

購入後はダイアログを閉じず、所持プルン・商品一覧・購入ボタンの状態を更新する。

初期実装では追加の購入確認ダイアログは設けない。商品選択と購入操作を分けることで誤操作を抑える。

## 5. 画面サイズ・レイアウトの振る舞い

| 項目    | 方針                    |
| ----- | --------------------- |
| 初期サイズ | 商品一覧と説明欄を無理なく表示できる大きさ |
| 表示位置  | 親画面の中央                |
| サイズ変更 | 初期実装では固定サイズを基本とする     |
| 商品数増加 | 商品一覧のみスクロール           |
| セリフ増加 | セリフ領域の大きさを維持          |
| 商品選択  | 各領域の位置・大きさを変更しない      |

特に重要なのは、商品を選択しても、商品一覧と説明欄の境界が動かないこと。

商品の説明文が長くても短くても、画面構造を一定に保つ。

## 6. 常設ショップ・行商人の共通化

両者は同じ画面構成を利用し、以下のデータだけを差し替える。

| 項目   | 常設ショップ     | 行商人         |
| ---- | ---------- | ----------- |
| 店舗名  | 常設ショップ     | 行商人         |
| 商人画像 | 常設店主       | 行商人         |
| セリフ  | 共通セリフ      | 共通セリフ       |
| 商品一覧 | 常設ショップの全商品 | 出現時に抽選された商品 |
| 購入操作 | 共通         | 共通          |

行商人は、出現期間中にショップを閉じて再度開いても、商品ラインナップが変化しないものとする。

また、購入済みの商品は行商人の抽選対象から除外する。

## 7. 将来の拡張候補

初期実装には含めないが、画面構造として拡張できる余地を残す。

- 商人ごとの専用セリフ

- 商品ホバー時の特殊セリフ

- 購入成功時のリアクション

- 条件付きセリフの抽選

- 商人画像の表情変化

- 商品ごとの専用説明演出

これらのために、現段階で専用の画面領域や複雑な制御を追加する必要はない。

## 9. 画面設計のまとめ

今回の設計で最も重視するのは、次の3点だよ。

① 商人と買い物をしている雰囲気

左側の商人画像とセリフを使い、単なる商品管理画面ではない、絵本的なショップを表現する。

② 一覧性と誤操作の防止

商品一覧から選択し、下部で効果を確認してから購入する。購入済み商品も確認できる。

③ 拡張しやすい共通構造

常設ショップと行商人の画面を共通化し、商人や商品が増えても基本レイアウトを変更せずに対応できるようにする。

これで、画面構成についてはCodexに実装を任せられる程度まで定義できたと思う。

ただし、これはあくまで画面設計。商品効果の計算、購入済み状態の管理、行商人の出現制御などは、別途ショップの機能設計として整理するのがよさそうだね。🌱

## 購入機能実装時の更新（2026-11-03）

- 価格は常設商品500 PLN・行商人商品1000 PLNとする。本節は初期画面設計の一律500 PLNに優先する。
- 行商人は1日目と10の倍数の日に表示。同じ日の再表示では商品を維持する。未所持から最大3種類を抽選し、購入した商品もその日は一覧に残す。
- 購入後の状態更新・効果適用を接続した。購入済み情報と累積効果はゲームごとに保持し、最初からやり直すと初期化する。
