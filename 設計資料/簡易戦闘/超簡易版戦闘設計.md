# 簡易戦闘設計 Ver.0

## 1. 目的・位置づけ

将来のオートバトル実装に先立ち、労働後に外敵から襲撃されるイベントをゲームループへ組み込む。

- **内部的には「戦闘処理」**として扱う。
- **ゲーム上は「ちょっとしたアクシデント」**として表現する。
- 現段階では戦闘計算・戦闘画面を実装せず、結果のみを適用する。
- プレイヤーが自発的に戦闘を開始することはできない。

## 2. Ver.0 の仕様

| 項目 | 仕様 |
| --- | --- |
| 発生タイミング | 労働終了後 |
| 発生条件 | 一定確率でランダム発生 |
| 発生確率 | **仮値：10%**（要調整） |
| 戦闘相手 | 外敵。個体・能力等の区別は現段階では不要 |
| 戦闘処理 | 省略（攻撃・防御・ターン処理なし） |
| 戦闘結果 | 必ず生還 |
| 体力減少 | 固定値 **10** |
| 体力下限 | **1**（戦闘によって体力0にはならない） |
| 報酬 | なし |
| 能力値・経験値の増減 | なし |
| プルンの増減 | なし |
| プレイヤー操作 | なし |
| 通知方法 | 労働結果への追記を基本案とする |

### 処理の流れ

1. プレイヤーが労働を実行する。
2. 通常の労働結果を確定する。
3. 労働終了後に戦闘発生判定を行う。
4. 戦闘が発生した場合、戦闘の経過を省略して体力を10減らす。ただし下限は1とする。
5. 労働結果に襲撃の発生と体力減少を追記する。

体力の更新例：`戦闘後体力 = max(1, 戦闘前体力 - 10)`

## 3. 表示案

労働結果の中に、戦闘が発生した場合のみ次のような文言を表示する。

> 帰り道で魔獣に襲われた！  
> なんとか逃げ切ったが、体力を10消耗した。

※ 表示文言は仮。実際の体力減少が10未満になる場合（残り体力が少ない場合）、数値表示は実際の減少量に合わせるか、数値を含まない文言にする。

## 4. 実装方針

- **戦闘発生判定**と**戦闘結果の適用**は分けて扱う。
- 戦闘の詳細ロジックを作り込まず、後からオートバトルへ差し替えられる構成にする。
- Ver.0 では専用戦闘画面は不要。労働結果への通知で完結させる。
- 発生確率は後から調整できる値として管理する。

## 5. 将来の拡張予定（Ver.0 の対象外）

- 複数の労働から選択でき、労働ごとに戦闘発生確率が異なる仕組み。
- 攻撃力・防御力などを用いたオートバトル。
- 敵の種類・強さ、勝敗、戦闘能力の成長。
- 危険度を選択できる仕組みが整った段階で、戦闘による体力0・ゲームオーバーを許容するか再検討する。

## 6. 未確定事項

- 戦闘発生確率の最終値（現時点では10%を仮置き）。
    - (コメント)労働種類を少し増やして、労働によって確率を変動させるので今決める意味が薄い
- 襲撃イベントの具体的な表示文言。
    - (コメント)簡易戦闘をオートバトルで実装する予定があるため、
- 労働結果画面での表示位置・見せ方。

---

**設計の基本原則：** 現段階の戦闘は、労働後に確率で発生する軽い損失イベントとして最小実装する。複雑な戦闘システムは後の段階で設計・実装する。
